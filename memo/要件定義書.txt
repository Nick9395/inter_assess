# 要件定義書：Inter_Assess
最終更新: 2026-09-28

※ 原稿の重複・混在を整理し、これまでに取り決めた仕様と矛盾する点を修正した。


### 1. 概要　目的・背景
就活・転職の面談練習と、自己理解の言語化を目的とする。

自分の学歴・職歴・考えを整理し、就活向けの言葉にする手助けをする。
模擬面接では、実際の面接に近い雰囲気で質疑応答を練習できる。


### 2. 対象ユーザー　誰が使うか
- 就職活動・転職活動をしている人
- 当面は個人利用。一般公開プロダクトにするかは未定


### 3. システム範囲　今回作るもの、作らないもの

【作るもの】
- ユーザー認証（登録・ログイン・ログアウト・パスワードリセット）
- 利用規約ページ
- 学歴・職歴プロフィールの登録・再利用・削除（練習データとは別）
- 面接官1人による音声＋テキストの模擬面接（質問数は開始時に 5〜10）
- 一部の質問に対する即興の深掘り（開始時に抽選。詳細は機能要件）
- 終了後の AI フィードバック（1練習につき1回）
- フィードバックの .docx ダウンロード
- 練習本文の手動削除

【作らないもの（今回）】
- 管理者画面・管理者権限
- 回答を見て面接全体の質問順や本問を組み替えること
- 回数無制限の深掘り
- リアルタイム採点
- 履歴書・職務経歴書ファイルのアップロード / OCR
- OAuth（Google ログインなど）
- 本番メール送信（Resend は将来）
- 決済
- 音声の外部 API（Whisper / TTS API は使わない）


### 4. 機能要件

【認証】
- アカウント作成できる
- 登録項目: ユーザー名（1〜20文字）、メールアドレス、パスワード（8〜16文字）、パスワード確認
- ログイン: メールアドレスとパスワード
- ログアウトできる
- パスワードリセットできる（開発中はブラウザでメール確認。本番メールは後回し）
- ログイン後はユーザー画面へ遷移する
- アカウント情報を変更できる
- アカウントを削除できる

※ メールアドレスの上限は 255 文字とする（原稿の 1〜30 文字では実在アドレスが入らないため）

【プロフィール】
- 学歴（最大2件）: 入学年月、学校名（偽名可）、学部学科コース（任意）、卒業年月（任意）、そこで学んだこと
- 職歴（最大3社）: 入社年月、退社年月（在職中は空）、会社の事業内容、役割、実績
- 氏名・住所・電話・メール・写真は持たない
- 練習データとは別にユーザーへ紐づけて保存し、何度でも使い回せる
- プロフィール削除は、フィードバック／練習本文の削除とは別操作

【模擬面接】
- 開始前に質問数を 5〜10 から選ぶ
- よくある質問をマスタとして約 10 問用意する
- 出題はマスタを型にし、プロフィール内容に絡めて開始時に質問を用意する
- 面接官は1人。質問は画面表示し、ブラウザ標準 API で読み上げる
- 回答は音声入力し、ブラウザ標準 API で文字化する
- 文字起こしを画面で確認・修正したあと、Enter で送信する

【深掘り（即興質問）】
- 開始時に抽選する。回答の良し悪しでは、対象問や回数を変えない
- 1回の練習で深掘り対象になる本問は 0〜4 問（4 は上限。0 もあり、全く深掘りしない練習もある）
- 対象に当たった本問は、必ず先に用意した質問を出し、回答を受けてから深掘りする
- 対象問の深掘り回数は 1〜3 回（開始時に問ごとに決める）
- 深掘りの文言は、その本問への回答を見て gpt-4o-mini が即興する
- 対象外の本問は、回答後すぐに次のマスタ質問へ進む
- API 失敗時は「質問を変えます」と伝え、その問の深掘りを打ち切って次のマスタ質問へ進む
- 失敗しても、練習全体の深掘り枠（最大4問）は消費した扱いでよい。残り枠があれば他の対象問で深掘りしてよい

【フィードバック】
- リアルタイム採点はしない。面談終了後に 1 回だけ生成する
- 含める内容:
  - 質問意図との一致
  - 説明の仕方
  - 課題と改善点
  - 「あなたはこういう人」という言語化
  - 模範解答例
  - 今の答え方だと次に来そうな深掘り質問と、返しの意図
- 簡単な点数化も行う。比較用に点数などの要約は残してよい
- 全文の履歴は DB に長く残さない。docx で書き出してローカル保存する
- 練習の本文（質問・回答・フィードバック）は手動で削除できる


### 5. 画面要件

- トップ画面: アプリ説明。未ログイン時は利用開始・ログイン・利用規約へ遷移
- サインアップ画面: アカウント登録
- サインイン画面: ログイン。パスワード再設定への導線あり
- パスワード再設定画面: リセット案内の送信、新しいパスワードの設定
- 規約画面: 利用規約
- ユーザー画面: ログイン後の起点。ログアウト。今後ここに面談開始・プロフィール・結果を置く
- プロフィール画面: 学歴・職歴の登録・編集・削除（今後）
- 面談画面: 質問表示・読み上げ・回答入力（今後）
- フィードバック画面: 結果表示と docx ダウンロード、本文削除（今後）


### 6. ユーザー権限
- 一般ユーザーのみ
- 管理者は作らない


### 7. データ要件

永続する:
- users（認証）
- education_entries（学歴。user に紐づく）
- work_entries（職歴。user に紐づく。最大3）

練習中〜ダウンロードまで置く。長く残さない（手動削除）:
- practices（1回の練習。質問数、状態、簡単な点数、深掘りの抽選結果）
- turns（質問文と回答テキスト。本問か深掘りかの区別）
- feedbacks（AI の JSON）

関連:
- user 1 : 多 education_entries / work_entries / practices
- practice 1 : 多 turns、1 : 1 feedbacks


### 8. 非機能要件
- 当面はローカル利用
- ログイン必須
- 個人情報（氏名・住所・連絡先）は入力させない。経歴も必要最小限
- 送信先の LLM は gpt-4o-mini（無料枠の学習利用を避ける）
- ブラウザは Chrome / Edge を想定
- 開発は全部 Docker。アプリ 3000、PostgreSQL 5432。volume 永続化。.env
- テストは Minitest


### 9. 外部連携
- OpenAI API（gpt-4o-mini）
  - 開始時: 本問の用意（1回）と深掘り対象・回数の抽選（アプリ側。LLM 不要）
  - 面談中: 深掘り文言の生成（対象問の回答後。最大 4問 × 3回）
  - 終了後: フィードバック生成（1回）
- メール: 今は letter_opener_web。将来 Resend
- 決済なし
- 音声の外部 API なし（ブラウザ標準）


### 10. 制約事項
- Rails 8 / Ruby 3 / PostgreSQL / Importmap / Tailwind CSS
- Hotwire、Solid Queue / Cache / Cable を使う。Node.js と Redis は使わない
- よくある質問マスタを約 10 問用意する
- 音声: ブラウザの Speech Recognition（入力）と Speech Synthesis（読み上げ）
- LLM へはテキストを JSON で渡す。返却も JSON。画面と docx、必要なら読み上げに使う
- 深掘りの有無と回数は開始時の抽選で決める。LLM は当たった問の「次の一言」だけ作る
- GitHub で管理する


### 11. 前提・未決事項

- フィードバック読み上げを必須にするか（画面表示と docx を正とする）
- 点数比較の画面を作るか、docx 同士の比較で足りるか
